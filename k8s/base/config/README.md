# Kubernetes configuration and secrets

## Production deployment

`k8s/overlays/prod` is the production path. It generates ConfigMaps from its
Kustomize literals and uses hashed names, so a configuration change rolls out
new Pods automatically. Update the host, trusted proxy CIDRs, external service
addresses, and image release tags before applying it. The Ingress assumes an
ingress-nginx controller in namespace `ingress-nginx` and a TLS Secret named
`video-host-tls`; adjust the Ingress and NetworkPolicies if your cluster uses a
different controller namespace. Provision the TLS Secret through your
certificate manager.

Secrets are deliberately not generated by Kustomize and must be provisioned
outside this repository (for example, with External Secrets, SOPS, or a secure
deployment secret store). Create the fixed names `backend-secrets`,
`ffmpeg-worker-secrets`, and `vod-secrets` in namespace `video-host` with the
keys listed in the `*-secrets.sample.yaml` files. Those sample files contain
placeholders only and must never be applied. `stringData` accepts clear text;
do not commit populated copies. The backend and VOD `vod-internal-secret` keys
must have the same random value.

MySQL, Redis, and an S3-compatible service are external dependencies and are
not created by these manifests. Ensure their configured DNS names and ports
are reachable from `video-host`. Egress remains available for these external
dependencies. The production NetworkPolicies restrict application ingress.

## Standalone base install

For a standalone base install, use the sample files as templates to create the
required ConfigMaps and Secrets. Do not apply these sample ConfigMaps on top of
the production overlay; that would create a second source of configuration.
The sample defaults refer to `mysql`, `redis`, and `minio` DNS names, which must
be provided by your cluster or changed to your external service endpoints.

## VOD ingress and configuration

`nginx/nginx.conf` is mounted by the local `docker-compose.yml` for development
and is not the Kubernetes configuration. `vod-nginx-config.sample.yaml` is the ConfigMap template used by the VOD
Deployment. The nginx container runs as UID 101 and listens on port 8080; its
Service exposes port 80. The Ingress terminates public TLS and routes `/vod/*`
to that Service. Set the worker's `vod-base-url` to the public Ingress origin
without a trailing `/vod` path.

The production overlay generates the VOD ConfigMap from `k8s/overlays/prod/nginx.conf`.
It routes mapping requests to `backend:3000` and reconstructs presigned S3
upstreams from the backend ConfigMap's endpoint, region, bucket, and path-style
settings. Virtual-hosted S3 URLs add the bucket to the upstream host; path-style
URLs retain the bucket in the URI. For HTTPS buckets with dots, the init
container selects path-style to match the AWS SDK's certificate behavior. Keep
the backend and worker S3 settings aligned. Both the init and nginx containers
run non-root. The init container copies its CA bundle and uses `envsubst` to
render nginx configuration. HTTPS upstream certificates are verified with the
mounted CA bundle.

To inspect the production rendering, run `kubectl kustomize k8s/overlays/prod`
from the repository root. Confirm the rendered Ingress host, TLS Secret, image
versions, trusted proxy CIDRs, generated ConfigMap names, and external service
addresses before applying it.
