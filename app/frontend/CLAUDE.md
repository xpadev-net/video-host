# Frontend development guide

## Project overview

This is the Japanese home media server frontend. It uses TanStack Start with React 19 for routing and production builds, and consumes the workspace Hono backend through a typed client. It includes video and series browsing, authentication, dashboards, HLS playback, and Niconico-style overlay comments.

## Runtime requirements

- Node.js 22.12 or newer
- pnpm 10 (the repository pins the package-manager version)

Run commands from the repository root. Build the backend declarations before frontend type checking or builds.

## Commands

```bash
pnpm install
pnpm -F @video-host/backend build
pnpm -F @video-host/frontend dev
pnpm -F @video-host/frontend lint
pnpm -F @video-host/frontend lint:fix
pnpm -F @video-host/frontend format
pnpm -F @video-host/frontend format:check
pnpm -F @video-host/frontend typecheck
pnpm -F @video-host/frontend build
pnpm -F @video-host/frontend start
```

`dev` and `start` use port 3000. Nitro emits a standalone production build with browser assets in `.output/public` and the server entry at `.output/server/index.mjs`.

## Technology stack

- TanStack Start and TanStack Router
- React 19 and TypeScript
- Tailwind CSS and Radix UI
- Jotai for shared state
- SWR for remote data
- Hono's typed client for the backend contract
- HLS.js for playback
- `@xpadev-net/niconicomments` for overlay comments
- Biome for linting and formatting

## Source layout

```text
src/
├── atoms/        # Jotai state
├── components/   # Feature-oriented React components
├── contexts/     # Runtime environment configuration
├── hooks/        # Data and UI hooks
├── lib/          # Typed Hono client and shared helpers
├── libraries/    # Existing utility modules
├── routes/       # TanStack file routes and server handlers
├── service/      # API service functions
└── styles/       # Global CSS
```

`src/routeTree.gen.ts` is generated by TanStack Router. Do not edit it manually.

## Environment variables

Public browser configuration uses Vite variables:

```bash
VITE_API_ENDPOINT
VITE_SITE_NAME
VITE_ENABLE_COMMENTS
VITE_REQUIRE_SIGNUP_CODE
```

`VITE_API_ENDPOINT` is required. Container builds embed placeholder values from `docker/.env.placeholder`; `docker/env-replacer.sh` replaces those placeholders in `.output/public` and `.output/server` at startup so client assets and server-rendered HTML use the deployment's runtime values.

## Implementation notes

- Add pages and server handlers under `src/routes` using TanStack file routing.
- The health endpoint is the `GET /api/healthz` TanStack server route and returns `{ "message": "OK" }`.
- Use the typed client in `src/lib/client.ts` when calling the Hono backend.
- Prefer Tailwind utilities for new styling and keep shared global styles in `src/styles/global.css`.
